# AGENTS.md

Guidance for AI coding agents working in the **sokketter** repository. See [README.md](README.md) for the user-facing overview, supported platforms, and supported devices.

## Project layout

Cross-platform C++17 project. Three first-party components plus vendored dependencies:

- [libsokketter/](libsokketter) — core library. Public API is [libsokketter/include/libsokketter.h](libsokketter/include/libsokketter.h); implementation lives in `sources/` (internal headers are **not** shipped).
- [sokketter-cli/](sokketter-cli) — command-line front end built on CLI11 ([cli_parser.cpp](sokketter-cli/sources/cli_parser.cpp)).
- [sokketter-ui/](sokketter-ui) — Qt6 Widgets GUI (AUTOMOC/AUTORCC/AUTOUIC, `.ui` files).
- [third-party/](third-party) — **vendored, do not edit**. `kommpot` is the USB/Ethernet communication layer sokketter is built on; `curl` and `googletest` are fetched by CMake ([ThirdPartyFetch.cmake](ThirdPartyFetch.cmake)).

## Build & test

Build locally by using Build.py (Windows, Linux, macOS). Build.py allows selecting which actions to perform (configure, build, test, package) by specifying `--stages` (default: all).

```powershell
python Build.py --stages CONFIGURE BUILD VERIFY
```

- Tests are opt-in via `-DSOKKETTER_ENABLE_TESTING=true` (GoogleTest, discovered with `gtest_discover_tests`). Run them with `ctest --test-dir build --output-on-failure`.
- Coverage: [get_coverage.sh](get_coverage.sh) (lcov, non-Windows only). CMake option is `-DSOKKETTER_ENABLE_COVERAGE=true`.
- Fake devices for testing without hardware: set the `LIBSOKKETTER_TEST_DEVICE_NUMBER` env var to the desired count.
- Linux requires the udev rules in [udev-rules/](udev-rules) for USB device access.

## Architecture

Power strips use an inheritance chain: public `sokketter::power_strip` → internal `power_strip_base` → `energenie_eg_base` → concrete devices (`gembird_*`, `energenie_*`) in [libsokketter/sources/devices/](libsokketter/sources/devices). Devices are matched to classes in [power_strip_factory.cpp](libsokketter/sources/devices/power_strip_factory.cpp) by USB VID/PID or Ethernet identity.

Device configuration is persisted as JSON (nlohmann) to `devices.json` under the platform storage path (`C:\ProgramData\sokketter`, `/Users/Shared/sokketter`, `~/.local/share/sokketter`) via [database_storage.cpp](libsokketter/sources/database_storage.cpp).

**Adding a supported device** touches several places consistently:

1. Add a value to the `power_strip_type` enum in [libsokketter.h](libsokketter/include/libsokketter.h).
2. Add the device class under [devices/](libsokketter/sources/devices).
3. Register it in [power_strip_factory.cpp](libsokketter/sources/devices/power_strip_factory.cpp) (both `supported_devices` and `create`).
4. Extend `NLOHMANN_JSON_SERIALIZE_ENUM` in [database_storage.cpp](libsokketter/sources/database_storage.cpp) and `power_strip_type_to_string` in [libsokketter.cpp](libsokketter/sources/libsokketter.cpp).

## Conventions

- Follow [.clang-format](.clang-format) (100 cols, 4-space indent, Allman-style braces). Trailing return types (`auto f() -> T`), `snake_case` for classes/functions/files, `#pragma once` + include guards, Doxygen `@brief` comments.
- Logging is spdlog: use the `SOKKETTER_LOGGER` macro in the library and `APP_LOGGER` in the UI, with the `SPDLOG_LOGGER_*` level macros. Never log secrets (e.g. authentication passwords).
- Public library symbols must be annotated with the `EXPORTED` macro (see [export_definitions.h](libsokketter/include/export_definitions.h)).
- Commits follow [Conventional Commits](https://www.conventionalcommits.org); the changelog is generated by git-cliff ([cliff.toml](cliff.toml)).

## Gotchas

- [Build.py](Build.py) is **GitHub-Actions-only** and raises `EnvironmentError` when run locally — use the raw `cmake` commands above instead.
- Sources are collected with recursive globs; adding a new `.cpp`/`.h` under an existing component requires re-running CMake configure.
